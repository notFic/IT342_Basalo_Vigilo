2.4  Detailed  Feature  Speciﬁcations  
Visitor  Status  Lifecycle  
To  prevent  ambiguous  states,  visitor  records  strictly  follow  these  allowed  status  
transitions:
 
Current  Status  Allowed  Next  Status  Trigger  /  Event  
Active  Checked-Out,  Auto-Closed,  Voided  
Visitor  enters  the  premises.  
Checked-Out  Voided  Staff  manually  checks  out  visitor.  
Auto-Closed  Voided  Scheduled  auto-close  time  is  reached  (default:  11:59  PM).  
Voided  (Terminal  State  -  None)  Admin  flags  record  as  invalid.

Screens:  Admin  Panel  ->  Create  Staff  Account

2.5  Acceptance  Criteria  
AC-1:  Successful  Visitor  Check-In  
➢  Given  I  am  a  logged-in  Staff  member  ➢  When  I  submit  the  new  visitor  form  with  valid  details  and  a  valid  ID  image  ﬁle  ➢  Then  the  system  stores  the  following:   ○  time_in  timestamp  ○  created_by  user  ID  ○  host_name  ○  visitor_type_id  ○  location_id  ○  status  =  “Active”  
11   

--- PAGE BREAK ---

○  ﬁle_url  path  ○  “Extended  Visit  =  true  (or  false)”  ➢  And  the  visitor  should  appear  on  the  Active  Logs  dashboard  
AC-2:  Successful  Visitor  Check-Out  
➢  Given  I  am  viewing  the  Active  Logs  dashboard  ➢  When  I  click  the  "Check-Out"  on  a  visitor  record  ➢  Then  that  visitor  should  be  removed  from  the  active  list  ➢  And  the  system  must  record  the  following:  ○  time_out  timestamp  ○  updated_by  user  ID  ○  status  =  “Checked-Out”  
AC-3:  Admin  Log  Voiding  
➢  Given  I  am  logged  in  as  an  Administrator  ➢  When  I  ﬂag  a  visitor  entry  as  erroneous  or  fraudulent  ➢  Then  the  record's  status  should  change  to  "Voided"  ➢  And  the  record  remains  stored  for  audit  purposes  ➢  And  the  system  sends  a  notiﬁcation  email  via  SMTP  to  the  facility  manager.  AC-4:  Scheduled  Auto-Close  Process  
➢  Given  there  are  visitor  records  with  an  "Active"  status  ➢  When  the  system  executes  the  scheduled  auto-close  process  at  the  deﬁned  
cut-off
 
time
 ➢  Then  records  not  marked  as  “Extended  Visit”  are  updated  as  follows:  ○  status  =  “Auto-Closed”  ○  time_out  =  11:59  PM  (system  cut-off  time)  ○  Updated_by  =  SYSTEM  ○  auto_closed  =  true  ➢  And  they  no  longer  appear  in  Active  Logs.  
AC-5:  Google  OAuth  Login  
➢  Given  I  am  a  Staff  member  with  a  registered  Google  account  ➢  When  I  click  "Sign  in  with  Google"  and  authenticate  ➢  Then  the  system  must  verify  my  identity  with  Google  ➢  And  generate  a  custom  JWT  for  my  session  ➢  And  grant  me  access  to  the  dashboard.

3.0  NON-FUNCTIONAL  REQUIREMENTS  3.1  Performance  Requirements  
●
 
API  response  time:  ≤  2  seconds  for  95%  of  requests  under  normal  load  
●
 
Web  page  load  time:  ≤  3  seconds  on  standard  broadband  connection  
●
 
System  supports  up  to  100  concurrent  authenticated  users  
●
 
Database  queries  for  visitor  search  complete  within  500ms  
●
 
Scheduled  Auto-Close  process  completes  within  60  seconds  
3.2  Security  Requirements  
●
 
HTTPS  for  all  communications  
●
 
Staff  authentication  implemented  using  secure  JWT-based  session  
management
 
●
 
Password  hashing  with  BCrypt  (salt  rounds  =  12)  
●
 
Protection  against  SQL  injection  
●
 
Uploaded  ﬁles  must  be  validated  to  accept  only  safe  image/document  formats  
with
 
a
 
maximum
 
ﬁle
 
size
 
of
 
5MB.
 
●
 
XSS  protection  via  input  sanitization  and  output  encoding  
●
 
Rate  limiting  enforced  at  100  requests  per  minute  per  IP  
●
 
Audit  ﬁelds  (created_by,  updated_by,  created_at,  updated_at)  must  not  be  
manually
 
editable
 
3.3  Compatibility  Requirements  
●
 
Web  Browsers:  Chrome,  Firefox,  Safari,  Edge  (latest  2  versions)  
●
 
Android:  API  Level  34  (Android  14)  required  for  the  mobile  companion  app  using  
XML-Based
 
UI
 
Layouts.
 
●
 
Screen  Sizes:  Mobile  (360px+),  Tablet  (768px+),  Desktop  (1024px+)  
●
 
Operating  Systems:  Windows  10+,  macOS  10.15+,  Linux  Ubuntu  20.04+  
3.4  Usability  Requirements  
●
 
A  new  Staff  user  should  be  able  to  complete  a  visitor  check-in  within  3  minutes  
without
 
training.
 
●
 
Interfaces  must  maintain  a  consistent  navigation  layout  across  all  screens.  
●

necessary.
